# 地図(新しく入る人向け)

どこに何があるかの索引。毎回読む骨格(思想・構造・入出力の約束・見た目と作業の共通の決まり)はリポジトリ直下の AGENTS.md(CLAUDE.md が読む)、分野の細かい決まりは .claude/rules/。決まりの正本は policy.md(方針)・plan.md(段階と構造)・verify.md(検査とログ)・避ける形.md(作らない形)。画面の言葉(ボタン・メニュー・欄の名前)は 用語表.md。各 crate の詳しい説明は `src/lib.rs` の先頭の `//!` にある。層は各 Cargo.toml の `[package.metadata.kmb] layer`(`cargo xtask verify` の点検 `xtask/src/layers.rs` が毎回向きを確かめる。plan.md「crate の分け方」、verify.md 1 節「点検」)。外から届く Issue と PR の仕分けと返し方は 受け方.md、製品名とアイコンの扱いはリポジトリ直下の TRADEMARKS.md。機能ごとの記録(作った物・決めたこと)は docs/機能/ の 1 機能 1 ファイルの断片に書く(docs/機能/README.md。plan.md の最後に足さない)。

## 画面の中の入口

- kmb-ui の `src` の直下は骨組み: 窓の枠 `frame_ui`・ツールバー `ribbon`・タブ `tabs_ui`・配置 `dock_ui`・キー `keys`・コマンド欄 `cmdline`・色 `theme`・設定 `settings_ui`。作業空間の画面は `design/`・`assembly/`・`machining/`・`render/`・`animation/`・`simulation/`、ホームとファイル(版の履歴と見比べを含む)は `files/`、`Workspace` の振る舞いは `workspace/`。
- 3D のビューは kmb-ui-view3d の `view3d.rs`(ウィジェット)と `view3d/`(描く物 `scene`・視点 `camera`・色 `look`・拾う `hit`・CPU の描画 `raster`)、GPU は `gpu3d.rs` と陰影の `gpu3d.wgsl`。設計の画面のビューの振る舞いは kmb-ui の `design/view_ui.rs` と `design/view_ui/`。
- 2D のスケッチのビューは kmb-ui-sketch の `view/`(1 コマは 視点 `mod.rs` → キー `keys.rs` → 道具の操作 `act.rs`・`act/` → 描画 `draw.rs`・`draw/`)。3D スケッチは `space3d/`(ビューは `view.rs` と `view/` の当たり判定・寸法・描画)。

## 見本

見本の文書の決まりは policy.md「決めたこと」の見本。中身は kmb-samples でコードから組み、文書のファイルは置かない。

| 見本 | 組む関数(kmb-samples) | 使う所 |
|---|---|---|
| 基準部品・基準部品と 2.5D の加工・基準部品と 3D の仕上げ | `reference_document`・`reference_cam_document`・`reference_cam_3d_document` | 利用者に見せる一覧 `kmb_bundle::Sample`(画面の `--sample`・CLI と MCP の `sample`)、画面の試験 |
| スケッチ・フィレットと面取り・スイープとロフト・外観などの見本 | `sample_document`・`sketch_tools_document`・`fillet_then_chamfer_document`・`sweep_loft_document`・`look_document` など(`src/lib.rs` の `pub use`) | 通しの試験と画面の試験(利用者の一覧には出さない) |

見本を組む部品は `sample::DocBuilder`・`sample::SketchBuilder`。kmb-samples には見本を使う通しの試験(`*_tests.rs`)も同じ所にある。

## よく使うコマンド(詳しくは verify.md 1・8 節)

- `cargo xtask verify` 変えた crate だけ。`--dependents-lower` はプッシュ前(組み立てと入口の層の手前まで。上の層は PR の CI の `--dependents`)、`--all` は全体、`--truck` は公開準備の時だけ。結果は verify.log の最後の `rc=` と「通過/失敗」の行で見る。
- `cargo xtask affected` 変えた crate の一覧だけ出す。
- `cargo xtask sweep` → `--yes` 古い target を消す。
- `scripts/cloud-target-cache.sh restore|save` クラウドで組み立て済みの target を使い回す(cargo より先に restore)。
- `scripts/install-nextest.sh`・`install-hakari.sh`・`install-deny.sh` クラウドのコンテナに検査の道具を入れる(無ければ verify が呼ぶ)。
- `scripts/取り込み.ps1 <ブランチ…>` PC でクラウドのブランチを取り込み、検査してプッシュする。ブランチは取得した時の先頭のままの時だけ消し、後から積まれていれば残して終了コード 2 で知らせる(試験 `pwsh -File scripts/取り込み/ブランチの削除.test.ps1`)。
- `scripts/ui-shot/drive.sh` クラウドで画面を撮る(`scripts/ui-shot/README.md`)。
- 依存や crate を足したら `cargo hakari generate` と `cargo hakari manage-deps --yes`(verify.md 2 節)。
- アプリ: `cargo xtask release`(release で作り、exe にこの PC のパスが残っていないかを数える。verify.md 12 節)。
