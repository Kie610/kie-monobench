# 機能が多い時の画面の重さを、測って元から減らす

- 日付: 2026-10-25
- 元の項目: 他のソフトの更新 2026-10-24 v10(長い一覧で見えない行を描かない。先に測る)
- 意図: 機能が何百もある文書で、画面の 1 コマが重くなり操作がもたつく。
- 仕分け: B・土台から作る(先に測り、重さの元を直す。行を描かない形は後で決める)

## 測った物

debug の組み立て、egui_kittest、押し出し 300 個(機能 600 個)、1400×900 の窓で 1 コマの時間。

| | 機能 20 個 | 機能 600 個(直す前) | 直した後 |
|---|---|---|---|
| 1 コマ | 9 ms | 192 ms | 約 125 ms |
| 編集パネル | 4.6 ms | 51 ms | 約 20 ms |
| ブラウザ | 3.9 ms | 44 ms | 約 45 ms |
| タイムライン | 0.9 ms | 23 ms | 23〜32 ms(揺れ) |

編集パネルの重さのほとんどは欄でなく、パネルに出す操作を選ぶための操作の一覧(全部のモジュールの `actions`)だった。押し出し・回転・スイープは、押せるかを決めるために毎コマ全部のスケッチの輪郭を JSON から読み直し(しかも読む前に JSON を丸ごと写していた)、レンダリングは押せるかを決めるために全部のボディの名前を作っていた。

## 作った物

- `kmb_cad::regions::has_profile`: 輪郭を読まずに、領域のある輪郭があるかだけを見る。`candidates` と押し出しの線だけのスケッチの判定が使う
- `Payload::from_value` は JSON を写さずに読む(すべての出力の読み取りが軽くなる)
- レンダリングの操作は、押せない理由をボディの名前を作らずに決める(`bodies_problem`)
- ブラウザの種類分けは記述子を丸ごと写さず区分だけ引く
- 試験 `crates/kmb-ui/src/design/extrude_tests.rs` の `the_quick_profile_check_agrees_with_reading_the_profile`(速い判定と読んだ時の答えが同じ)

## 作らなかった物

- 見えない行を描かない形: ブラウザとタイムラインの行は MCP の `ui_*` とコマンド欄が名前で探すので、描かないと見えない行を AI が押せなくなる。描かない行にも名前を残して押せるようにするかを決めてから作る
- 残りの重さ: ブラウザの行ごとの様子(`status_line`・`health`・隠したか)と、モジュールの操作の一覧が毎回 `visible_bodies` で全部の機能の記述を読む所。1 コマの中で使い回す控えを持つ形が要る
