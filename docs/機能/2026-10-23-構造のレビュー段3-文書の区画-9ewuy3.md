# 文書のモジュールごとの区画・保存形式の版 4・シーンの設定を文書ごとに

- 決定: シーンの設定を文書ごと
- 日付: 2026-10-23

## 作った物

タイムラインに乗らない文書の中身を、コアの上の階の項目でなく、それを扱うモジュールが名乗る「区画」に置けるようにした。使う人から見える振る舞いは変えない。

- コア(kmb-core の section.rs): 文書に `sections`(鍵 → 版と JSON の値)を持たせた。モジュールは `SectionType`(鍵・版・名前・1 版ずつの移し方・決まり・空か)を実装し、組み立てで `Registry::declare_section` で名乗る(同じ鍵の二重の名乗りは組み立ての時に止める)。読むのは `DocumentData::section::<T>()`、書くのは汎用の変更 `Op::SetSection`(取り消しは前の値に戻す逆の変更)と、操作の結果の `Edit::SetSection`。
- 知らない区画(新しいアプリやほかのモジュールが書いた物)は読んだまま書き戻す。区画の中の知らない項目も、区画の型の根の `#[serde(flatten)]` の残りで書き戻す。区画の版が新しい時は読まず、上書きの変更も誤りにする(黙って項目を落とさない)。
- 保存形式を版 4 にした(`kmb_core::FORMAT_VERSION`)。版 3 の上の階の `motion_studies`・`contacts` は、読む時に区画 `asm.motion`・`asm.contacts`(区画の版 1)へ移す。
- モーション スタディと接触セットの型(kmb-core の motion.rs・contact.rs)を kmb-interchange へ移し、組立(kmb-asm)が区画として名乗る。専用の変更 `Op::SetMotionStudies`・`Op::SetContacts` はやめ、`Op::SetSection` に寄せた。画面は `kmb_interchange::motion::studies`・`contact::of` で読み、`kmb_session::edit::set_section` で書く。
- 入出力の一覧(docs/入出力.md)に名乗られた区画の表を足した。
- レンダリングのシーンの設定(3-7): 文書の区画 `render.scene` に置く。設定の窓・CLI・MCP で変えると、PC 全体の値(前回使った設定。データフォルダの settings.json)と今の文書の両方を変え、文書の側は取り消せる(「レンダリングの設定を変える」)。区画の無い文書(前からの文書と新しい文書)は前回使った設定で描く。仕組みは汎用で、拡張点 `Extension::document_settings`・`document_settings_edit` と `Headless::settings`・`set_settings`。

## 移さなかった物(理由)

- アニメーションの手順・見た目の割り当て・材料・構成の表は、今回は上の階のまま。読む側が層をまたいで多い(アニメーションはレンダリングの書き出しとジョイントの引きの `Dof`、材料は解析と点検、構成は再計算)ので、読む口を区画に揃えてから 1 つずつ移す。
- ボディの長く使える ID(`BodyId`)は、今のボディの根の機能の ID をそのまま使い、型だけ分ける形を次の分で入れる。

## 決めたこと

- 区画の鍵は名乗るモジュールの頭を付けた英小文字(`asm.motion` のように)。版はモジュールが持ち、1 から数える。
- 空の値を書くと区画を外す(空の文書に `sections` を書かない)。
- シーンの設定を開いただけ・描いただけでは文書に書かない(変えた時だけ書く)。前からの文書を開いて保存しても中身が変わらないようにするため。

## 試し方

`cargo xtask verify --all`。kmb-core の区画の試験(取り消し・保存と読み直し・古い版の移し・新しい版を読まない・知らない区画と項目が残る・版 3 からの移し・鍵の二重の名乗り)、kmb-solid の組立の試験(モーション スタディ・接触セット)、kmb-mcp の `the_render_scene_is_kept_per_document`(文書ごと・新しい文書は前回の値・取り消し・誤りの値)、画面の台本。画面では、文書 A でシーンの設定の幅を変え、新しい文書を作って別の値にし、A のタブへ戻ると A の値に戻ること。
