# スケッチの番号を使い回さない・空のスケッチの言葉

- 日付: 2026-10-25
- 元の項目: 2026-10-23 k2・2026-10-20 s16
- 意図: スケッチの点を消して描き直すと、穴や回転の軸・拘束・寸法が黙って新しい点に付き替わる(k2)。何も描いていないスケッチに「完全拘束」と出て、描き終えたと勘違いする(s16)
- 仕分け: A・作る(k2 は番号を「今ある最大+1」で配っていた crates/kmb-sketch/src/edit.rs の `next_entity_id`・`next_constraint_id`。s16 は状態の言葉が 3 か所 crates/kmb-ui-sketch/src/view/measure.rs・space3d/mod.rs・crates/kmb-sketch/src/commands.rs にあり、点が無くても解は「完全拘束」になる)

## 作った物

- スケッチに次に配る番号の控え(`Sketch::next_ids`、要素と拘束)を持たせ、消した番号を配らない。控えの無い古いスケッチは今ある最大+1 から数える(読み替えは要らない)。保存には控えが付く(控えが無い時は書かない)。
- 読み込んだ形を足す(`insert_shapes`)も控えから数える。描く間に吸い付く先を仮に足して後で詰める所(kmb-ui-sketch の snap.rs)は、元のスケッチが配った番号の最後(`Sketch::last_ids`)から詰め、詰めた後の続きを控えにする(消した番号へ詰めない)。
- 何も描いていない(点も円も無い)スケッチの状態の言葉を「まだ形がありません」(`kmb_sketch::NO_SHAPE`)にした。画面のスケッチの題・拘束と寸法のパネルの札・3D スケッチの題、CLI と AI の説明が同じ言葉を読む。札の色は「動ける」と同じ(緑の「済み」の色にしない)。

## 決めたこと

- 解き方の中で候補の拘束を仮に足して調べる所(solver.rs の `determined_by` など)は写しの上で使い捨てるので、控えを使わない。
- 文書の保存形式の版は上げない(スケッチの欄はモジュールの中身で、知らない欄は前の版のアプリでは読めない。新しい版は前の版で読まない決まりのまま)。

## 試し方

- `kmb-sketch` の `removed_ids_are_not_reused`(消して足しても番号が大きくなる、保存して読み直しても残る、古いスケッチは最大+1)・`blank_sketch_is_not_fully_constrained`。
- `kmb-ui-sketch` の `a_new_sketch_says_it_has_no_shape_yet`(新しいスケッチで「まだ形がありません」、線を引くと消える)。
- 台本 `apps/kmb-app/tests/ui/空のスケッチ.jcs`。
