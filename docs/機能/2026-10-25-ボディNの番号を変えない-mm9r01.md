# 「ボディN」の番号を、ほかのボディを結合で使っても変えない

- 意図: 前のボディを結合で使うと、名前を付けていない「ボディN」の番号が黙って変わり、どれがどれか分からなくなる。
- 仕分け: A・作る。「ボディN」の N は今見えているボディの中の順だった(crates/kmb-core/src/recompute.rs の `body_labels`)。画面に同じ数え方の写しがあった(crates/kmb-ui/src/design/browser_ui.rs の `body_numbers`、menus_ui.rs の `body_name`)。
- 日付: 2026-10-25

## 作った物

- `kmb_core::body_labels` の N を、文書でボディを作った機能のうち何番目かにした: ソリッドの区分の機能で読むボディが無い物(元を残す機能の写しを含む)と、見えているボディの元を、タイムラインの順に数える。結合で見えなくなったボディも数えるので番号が詰まらない。公開の項目は変えていない。
- ボディを最初に作った機能を探す `body_root` と同じ 1 歩(`reads_body`)を使う。
- 画面の写しをやめた: ブラウザ・部品の木・`body_name_of` は `body_labels` の名前を使う(`body_numbers` は名前・最初に作った機能・行を返す)。
- 試験: crates/kmb-solid/src/tests.rs の `body_numbers_stay_when_another_body_is_combined_away`(直す前は ["ボディ1", "ボディ2"] で落ち、直した後は ["ボディ1", "ボディ3"])。

## 変わったこと

- 前の文書でも、結合で消えたボディの後のボディは番号が前より大きく出る(ボディ2 → ボディ3 など)。付けた名前は変わらない。
