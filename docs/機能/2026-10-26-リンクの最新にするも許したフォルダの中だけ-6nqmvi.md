# リンクの「最新にする」も許したフォルダの中だけを読む

- 日付: 2026-10-26

## 作った物

AI(MCP)は作業フォルダと許したフォルダの外を読まない。これまで確かめていたのは道具のファイルと操作のファイルの引数・設定のファイルの欄だけで、リンクで組み込んだ部品の元のパスは文書のデータにあるため確かめていなかった。AI が `set_feature` で元のパスを外へ書き換えて「最新にする」を動かすと、外の文書を読んで写しに取り込めた。

- kmb-core の `Context` に、操作が文書のデータから開くファイルを確かめる口 `files`(`FileGate`)と `Context::open_path` を足した。`None` なら確かめない(人が画面や CLI から動かす時)。
- kmb-session の `Roots` が `FileGate` を持つ。`Picks::files` で渡す(MCP は `Headless::run_with` と `Handled::into_ran`)。MCP の `run_action`(`batch` も)は許したフォルダを渡し、画面は AI から来た頼みで動く操作にだけ渡す。
- リンクの挿入・最新にする・選び直すは、元を読む前に `open_path` を通す。外なら理由を出して断り、文書は変えない。
- 文書の要約(`Headless::status_in`。MCP の答えに付く `links`)でリンクの様子を調べる時も、外の元は読まず「元が無い」と同じに見せる。

## 決めたこと

- 文書のデータに書いたパスは、書く時ではなく開く時に確かめる(AI が文書のファイルを直に書いて開いても同じ確かめを通る)。

## 試し方

- 試験 `kmb-mcp` の `a_link_rewritten_to_point_outside_is_not_read`: 元のパスを外へ書き換えると様子は「元が無い」になり、「最新にする」は断る。中へ戻せば通る。

## 残り

- 画面がリンクの様子(元が変わったかの印)を調べる時は、人の操作なので確かめない。
