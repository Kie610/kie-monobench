# 操作の引数の宣言と、ID で操作を動かす run

- 日付: 2026-10-22

## 作った物

構造のレビュー(2026-10-21)の段 1 の前半(根本原因 R1「約束が型でなく文字列や JSON の字面」の、操作の引数の分。指摘 D1・D3・D12・D14)。

- kmb-core に `args`(`Arg`・`ArgKind`・`check_args`)を足し、`Action::args` で操作が受け取る引数を宣言する。`Extensions::run` が実行の前に宣言で確かめる: 知らない鍵(打ち間違い)・型の違い・無い必須の引数は誤り、単位つきの式(`"0.002 in"`・`"90 deg"`)は宣言の単位の数に直す、省いた引数には既定を入れる。前は `Context::args` が自由な JSON で、知らない鍵は黙って捨てて既定で動いた。
- 操作は引数を `cx.arg` などで読み、読んだ鍵を記録する。宣言に無い鍵を読んだ操作は debug の組み立てで誤りになる(足し忘れを試験で捕まえる)。`cargo xtask checks` の層の点検は、コアの外で `cx.args.get(` を直に呼ぶ所を落とす。
- 引数を読む約 25 ファイルの操作に宣言を書いた(書き出し・レンダリング・加工・設計・組立・スケッチ・解析)。既定は宣言と読む所で同じ定数を使う。一覧に出さない操作は `Extension::unlisted` で宣言する(部品を引いて動かす `asm.drag_position`、段の帯の段と再生はシミュレーションの格子)。宣言が無ければ引数を受け取らない。
- CLI に `jc actions <文書>`(ID・使えない理由・引数の型・単位・既定。`--json` も)と `jc run <文書> <ID> --arg 鍵=値 … [--selected] [--input] [--out]` を足した(D12)。コマンド欄と MCP の `app` に `actions`・`run` を足した。MCP の `actions` は引数の宣言も返す。
- 画面の無い道(`Headless::run`)とコマンド欄の `run` は、使えない操作を理由つきで断る(D14)。前は確かめずに走らせた。CLI・MCP でセットアップを省いた時(`jc gcode`・`jc sim`・MCP の gcode・simulate)は、初めのセットアップを選んでから渡す。前は加工の操作の中に「選んでいなければ初めのセットアップ」という画面と違う省略があり、ボタンは使えないのに画面の無い道では動いた。
- 画面が全部の書き出しに渡していた隠したボディ・視点(`exclude`・`view`・`camera`)と段の帯の時刻(`time`)は、宣言した操作にだけ渡す。CLI・MCP の `export` も、受け取らない操作に `format`・`ascii`・`each` を渡さない。

## 決めたこと

- 操作は受け取る引数を `Action::args` で宣言し、`cx.arg`・`cx.arg_f64`・`cx.arg_str` で読む(docs/plan.md「コア API の考え方」)。
- 引数の長さの数は mm、角度は deg。文字なら単位つきの式でもよい。

## 試し方

- `jc sample a.json` の後、`jc actions a.json` に `io.export_stl` の `tolerance(長さ mm、既定 0.01)` が出る。
- `jc run a.json io.export_stl --arg tolerence=0.1 --out x.stl` は「引数 tolerence はありません(使える引数: exclude・tolerance・ascii・each)」で止まる。`--arg "tolerance=0.002 in"` は書ける。
- アプリのコマンド欄で `actions`、`run cad.add.sketch plane=yz` を打つと、YZ 平面のスケッチが足される。
