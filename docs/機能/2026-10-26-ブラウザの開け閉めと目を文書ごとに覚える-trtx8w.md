# ブラウザの開け閉めと目を文書ごとに覚える、探した行を畳んだ所から開く

- 日付: 2026-10-26
- 意図: 文書を開き直すたびに、ブラウザの開け閉めや原点・ボディの目を付け直す手間がある。3D の面から「ブラウザ内を検索」「タイムライン内を検索」をしても、探した行が畳んだ部品やグループの中に隠れて見えない。
- 仕分け: A・作る(開け閉めと目は画面の状態として前からある。覚える所と、探す時に開く所を足した)

## 作った物

- 文書ごとの見え方を覚える(`crates/kmb-session/src/doc_view.rs`、`crates/kmb-ui/src/files/doc_view_ui.rs`)。覚えるのは、ブラウザの木の枝の開け閉め、原点の目、スケッチ・ボディのまとまりの目、行の目(使われて自動で隠れたスケッチは除き、目を開けて出したスケッチは出したまま)、ボディの目、畳んだタイムラインのグループ。変わったらボタンを離した時に書き、文書を開いた時(開くのをやめて前の文書へ戻った時も)に戻す。
- ブラウザの木の開け閉めを egui の記憶から文書ごとの状態(`DocState::tree_open`)へ移した。鍵は枝の鍵の文字(`browser_ui::tree_key`)。
- 「ブラウザ内を検索」は、文書の行と、ボディの入っている部品と親の部品(部品に入っていなければボディのまとまり)を開く。「タイムライン内を検索」は、探した機能を含むグループを開く(`crates/kmb-ui/src/design/find_ui.rs`)。
- 試験: `crates/kmb-ui/src/assembly/components_tests.rs` の `the_browser_tree_and_eyes_come_back_on_reopen_and_find_opens_folded_rows`、`crates/kmb-session/src/doc_view.rs` の試験。

## 決めたこと

- 置き場は文書のファイルでなくデータフォルダの `doc-views.json`(文書のパスごと、新しい順に 200 件)。開け閉めや目で文書を「変更あり」にせず、取り消しの履歴にも乗せないため。読めなければ既定の見え方で開く。安全モードでは読みも書きもしない。
- ファイルを移したり名前を変えたりすると、前の見え方は引き継がない(既定で開く)。
- 3D で選んだだけでボディの行を開いて見せる、全部開く・閉じる、作業中の部品の外を囲み選択で選ばない、の 3 つは見せ方を決めてから作る。
