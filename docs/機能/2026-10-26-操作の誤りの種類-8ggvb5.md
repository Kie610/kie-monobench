# 操作の誤りの種類

- 日付: 2026-10-26

## 作った物

- 拡張点の操作 `Extension::run` と `Extensions::run` は `Result<Outcome, Problem>` を返す。CLI の終了の番号と MCP の答えの `kind` は、操作が書いた種類をそのまま使う。
- 文字列の誤りは `?` と `.into()` で入力の誤り(`ProblemKind::Input`)になる。機能の側は文字列の誤りのまま書いてよく、種類の違う誤りだけ `Problem::new` で書く。
- 種類を書いた所:
  - 知らない操作・引数の確かめは入力の誤り。宣言していない引数を読んだ操作(作りの誤り)は計算の誤り。
  - ファイルを読めない・書けない・消せない時はファイルの誤り: リンクの元の文書、STEP の読み込み、加工のテンプレートの読み書きと削除、加工の既定の読み込み、デカールの絵、レンダリングの書き出し。中身が違うファイル(JSON の形が違うなど)は入力の誤り。
  - 加工の操作でセットアップが無い・選んでいない時は使えない操作の誤り。
- `Headless::run_with` は、知らない操作に近い ID を添える時も種類を保つ。

## 決めたこと

- 機能の中の計算の関数は文字列の誤りのままにし、操作の入口(`run` と、そこから呼ぶ関数)だけを `Problem` にする。時間のかかる仕事の結果(`JobReport`)は文で返すので、種類を持たない。

## 試し方

- `cargo test -p kmb-core actions_check_their_arguments_against_the_declaration`(知らない操作は入力、宣言していない引数を読むのは計算の誤り)。
- `cargo test -p kmb-cam-commands defaults_can_be_exported_and_imported`(形の違うファイルは入力、無いファイルはファイルの誤り)。
