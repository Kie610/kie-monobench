# 配る exe にビルドした PC のパスを残さない

- 日付: 2026-10-24

## 作った物

- `cargo xtask release`: アプリを release で作る時だけ、rustc の `--remap-path-prefix` でホーム・rustup・cargo・リポジトリ・target の頭を短い名前に置き換え、作る前と後の exe に残るこの PC のパスを数える(`パス: 前 N 件 → 後 M 件`)。後に残れば失敗にする。取り込みのスクリプトはこれで作り、件数を要約に出す。
- `cargo xtask paths <ファイル>...`: 配るファイルに残るこの PC のパスを数える(大文字と小文字を区別せず、UTF-8 と UTF-16LE)。
- SMLib(C++)の `__FILE__`: smlib-sys と中継層(kmb-kernel-smlib)が、ソースと見出しの場所をパッケージのフォルダからの相対のパスで渡す。
- C の依存の `__FILE__`: release の時だけ `CFLAGS`・`CXXFLAGS` に、MSVC は `/d1trimfile:`、gcc・clang は `-ffile-prefix-map` で同じ頭を消す引数を足す(PC の取り込みで lzma-sys の xz の見出し `lzma_common.h` が 1 件残った。MSVC は見出しを探した場所を絶対のパスにする)。
- `cargo xtask sweep` の release の問い合わせにも同じ引数を付ける。

## 決めたこと

- cargo の `trim-paths` は Rust 1.99 でも安定版で使えない(実測)。`.cargo/config.toml` には PC ごとのパスを書けないので、release の時だけ xtask が `--config target.'cfg(all())'.rustflags=[...]` で渡す。debug の検査の組み立ては変えない。
- Linux の kmb-app の release で、直す前 1245 件(依存のソースの場所 1118・SMLib 52・target の生成物 7 ほか)→ 直した後 0 件。PC(MSVC)では 2203 件 → 1 件(lzma-sys)で、C の引数を足して直した。

## 試し方

`cargo xtask release`(前後の件数を出す)。数える所の試験は xtask の `release::tests`。手順は docs/verify.md の 12 節。
