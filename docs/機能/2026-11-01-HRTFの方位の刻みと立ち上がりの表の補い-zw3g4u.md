# HRTF の方位の刻みと立ち上がりの表の補い

- 決定: 音の解析とHRTF
- 日付: 2026-11-01

## 作った物

- `regrid` の欄 `azimuth_step`(輪の双線形の時だけ、度): 方位がこの刻みの倍数でない点を使わない。各輪に刻み(1°)の点のほかに端数の方位の点が足された格子で、刻みの点だけを混ぜる。極に方位の違う点が並ぶ時(天頂の多方位の輪)は刻みの点だけの平均、極の点がすべて外れる時(天底の 1 点など)はその点をそのまま使う。空なら全部の点を使う(今までと同じ)。
- `table` の欄 `onset_method`: 遅延の表の方向の立ち上がりを、集まりの方向から補う替え方(`nearest` 既定・`triangle`・`bilinear`)。集まり(例 2° の輪)より細かい遅延の格子(例 0.5°)で、間の方向の立ち上がりを隣の値の間に滑らかに入れる。半スペクトルは今までどおり最近傍。

## 決めたこと

- 2 つとも既定は今までの振る舞い(全部の点を使う・最近傍)のままにし、手順で選ぶ。比べた表に合わせるのは手順の側で、ほかの手順の結果を黙って変えないため。
- 極は今までどおり、極に並ぶ点の平均(1 点ならその点)を使う。初めに試した「極の点を捨てて一番上の輪の平均で埋める」選択は、実測の D1 で差を大きくした(天底の 1 点と天頂の多方位の輪を捨てるため)ので入れない。
- `azimuth_step` は双線形の時だけ選べ、0 より大きく 360 以下。外した点の数は処理の記録とログに書く。
- 輪の双線形で同じ仰角・極・刻みの倍数と見なす許し幅は 1e-3°。SOFA の方向は float32 で持つことが多く、1° の格子でも 1e-5° ほどずれる(KU100 で最大 7.6e-6°)。1e-6° では刻みの点を外したり、天頂の輪を極と見なさなかったりした。
- 立ち上がりの補いは鳴らす立ち上がり(遅れ + 輪の枠の立ち上がり)を重みで混ぜる。共通の遅れはその後に引く。

## 確かめたこと

- 試験(3 本): 方位と仰角に float32 ほどのずれ(7.6e-6°)を入れた格子でも、刻みの点を外さず、同じ輪にまとめ、89.99999° の輪を天頂と見なす(許し幅 1e-6° では落ちることを確かめた)。 5 本の輪に方位 116.6° の端数の点、天頂に 362 方位の輪、天底に 1 点を足した格子で、`azimuth_step` 1 では端数の点を混ぜず 116°・117° の点だけで補い、天頂は 360 点の平均、天底は 1 点、外した 7 点を記録に書く。指定しなければ端数の点を使う。三角形での指定と刻み 0 は誤り。30° の輪の集まりから 10° の遅延の表を作ると、`bilinear` は仰角に線形な立ち上がりをそのまま補い、最近傍では段になる。手順の JSON の `onset_method` で選べる。
- 手元の 1 回の確かめ(試験の外、PC の CLI で KU100・D1 の実測): `onset_method` を `bilinear` にすると、KU100 の立ち上がりの差の 99% は 0.34 → 0.06 sample、両耳の時間差の 99% は 11.4 → 1.8 µs。大きさの差は最大 0.008 dB のまま。D1 の輪の間の大きな差(仰角 −12°・方位 116.59° で 18.7 dB)は、D1 の各輪にある 1° 刻み以外の 40 点を補いに使うことから来ると確かめた(比べた表は 1° の点だけを使う)。`azimuth_step` 1 を D1 にだけ付けた比べ直し(5e97309)では、D1 の加工の差は中央値 0.0001・99% 0.19・最大 7.36 dB、1 dB 超は 317 → 128 方向で、仰角 −80〜76° では 0 方向。残りはすべて仰角 76° より上。KU100 にも付けると壊れた(最大 36.2 dB)のは、許し幅 1e-6° で float32 の方位を刻みの点と見なさなかったため(許し幅を 1e-3° に直した。直した後の比べ直しは not-run)。
