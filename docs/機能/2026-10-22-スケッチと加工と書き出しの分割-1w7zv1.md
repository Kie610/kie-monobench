# 3D スケッチ・プログラムの組み立て・視点の書き出しを別の crate に分ける

- 日付: 2026-10-22

## 作った物

構造のレビューの段 4 の E7・E8・E14 の残りと、E12 の jc-io-stl の分割。画面の見た目と操作は変えていない(操作の並びは `Action::before` で前と同じに保つ)。試験は移しただけで消していない。

- E7: 3D スケッチの数値の解き方(数値微分のヤコビ行列・最小ノルムのガウス・ニュートン法・拘束ごとの階数・決まっていない変数)を `jc_sketch_solver::rows` に移した。2D と同じく、解き方の作り直しは解き手の crate で比べられる。jc-sketch は nalgebra に依存しなくなった。
- E8: 3D スケッチを `jc-sketch-3d` に分けた(jc-sketch の `space/` と「3D スケッチを追加」の操作)。寸法の名前の付け方と式の計算は `jc_sketch::dims`(`DimConstraint`)で 2D と 3D が同じ部品を使う。
- E14: セットアップごとのプログラムの組み立て・G-code・シミュレーションのつなぎ・空振りの削除・段取り表を `jc-cam-program` に分けた。文書と登録表だけで決まる部分で、画面の操作を知らない。jc-cam-commands は同じ名前で出し直すので使い手は変えていない。
- E12: 今の視点の線の DXF・SVG の書き出しを `jc-io-view` に分けた。書き出すボディ(見えるボディから引数 `exclude` を除く)は `Context::export_bodies` としてコアに置き、jc-io-stl と jc-io-view が共に使う。
- 点検: 消えたテストの点検は、同じ名前のテストが別の crate へ移っただけなら消えたと数えない(Kie 2026-10-22)。丸ごと消した crate のファイルも数える。nalgebra を通常の依存に持てるのは jc-sketch-solver・jc-fea・jc-flow だけ。

## 決めたこと

- ボディからの写し(reference・section・silhouette・origin)を jc-sketch-project に分けるのはやめた。2D のスケッチの計算そのものが投影でこれらを呼ぶので、分けると依存が逆になる(レビューの「使う側なので依存の向きは保てる」は誤り)。
- 再利用(既定とテンプレート)と再生・動画は jc-cam-commands に残した。加工を足す時に既定を当てる、再生の状態を持つ、など操作の状態と結び付いているため。分けるなら、既定を当てる仕組みを操作の外から渡す形が要る。
- jc-io-stl の名前(STL・STEP・3MF の書き出し)は今のまま。名前を jc-io-mesh などに替えるかは別に決める。

## 試し方

- `cargo nextest run -p jc-sketch-solver -p jc-sketch -p jc-sketch-3d -p jc-ui-sketch -p jc-cam-program -p jc-cam-commands -p jc-io-stl -p jc-io-view -p jc-bundle`。
- 画面: 作成のメニューの「スケッチを作成」の次に「3D スケッチを追加」、ファイルのメニューの「STEP をボディごとに書き出す」の次に視点の DXF の 2 つ、3MF の次に視点の SVG が前と同じ順に並ぶ。
