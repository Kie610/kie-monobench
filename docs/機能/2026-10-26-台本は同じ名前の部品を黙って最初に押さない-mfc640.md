# 台本は同じ名前の部品を黙って最初に押さない

- 日付: 2026-10-26
- 意図: 画面の台本が、同じ名前の別の部品を黙って押したまま通り、確かめたつもりの操作を確かめていない
- 仕分け: A・作る。番号の無い部品の名前は、合う物が幾つあっても最初の物を押していた。

## 作った物

- コマンド欄・台本・MCP の `ui_*` の部品の探し方(kmb-ui `drive::Query::one`)は、番号(`#2`)の無い名前に幾つも合うと、押さずに誤りにして候補を `#1:`・`#2:` で挙げる。役割(`button:` など)か番号で 1 つに絞る。
- 欄の名前のラベルと、その名前を持つ欄・入切・一覧・スライダ(同じ行のすぐ隣)は 1 つの物として数える。
- `select` は、押した後に一覧の値が別の項目へ替わったら誤りにする(選んで足す一覧は値が「選ぶ」へ戻るので、元のままなら通す)。
- アプリの台本(apps/kmb-app/tests/ui)で幾つも合っていた所に、今まで押していた物を役割か番号で書いた。1 か所は「OK」が案内の字のラベルに当たっていたので、ボタンを押すようにした。
- `expect … missing` が `#n` を見ること、スライダの横の数の欄に Tab の確定で値が入ることは、前から直っていて試験がある(kmb-ui `expect_with_a_number_looks_at_that_one`・`typing_into_a_slider_number_field_sets_the_value`)。

## 試し方

- 試験: kmb-ui `a_name_that_matches_several_parts_fails_instead_of_pressing_the_first`(直す前は番号の無い「+」を押して通っていた)。
- アプリの台本: `cargo test -p kmb-app --test screens ui::`。
