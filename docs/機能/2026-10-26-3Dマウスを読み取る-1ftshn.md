# 3D マウスを読み取る(Windows・Linux)

- 日付: 2026-10-26
- 意図: 3D マウスを持つ人が、片手で形を回しながらもう片手で選びたいのに、JC では機器が働かない。探す時にほかの機器(キーボード)を取り違えたり壊したりしないことも要る。
- 仕分け: B・土台から作る(JC に機器を読む所が無いので、まず読み取りだけを作る。視点の動かし方と設定は続きで作る)

## 作った物

- 新しい crate `kmb-ui-mouse3d`(層 ui、egui を知らない)。`open()` で裏のスレッドが機器を探して読み、画面は毎コマ `Mouse3d::snapshot()` で 6 軸の値(-1〜1)と押されたボタンと状態を受け取る。試験用に `Mouse3d::fake()` と `feed`。
- 探し方: HID の用途が多軸の機器(Generic Desktop / Multi-axis Controller、0x01/0x08)で、会社の番号が 0x256F・0x046D の物だけ。番号だけでは決めない(同じ番号のキーボード・マウスを外す)。
  - Windows: SetupDi で HID を並べ、読み書きの権限なし・共有で開いて番号と用途だけを見る。読む機器だけを読み取りで開き直し、重ねた I/O で読む(200 ms ごとに止まる合図を見る)。
  - Linux: `/sys/class/hidraw/*/device/` の `uevent` と `report_descriptor` の最初の集まりの用途を見て、`/dev/hidrawN` を読み取りだけで開く。開けなければ状態を「権限が無い」にし、設定に udev の規則の例を出す。
  - そのほかの OS は「この OS ではまだ使えない」。
- 報告の解読(`report` の純関数): 報告 1 = 移動(中身 12 バイトなら移動と回転)、報告 2 = 回転、報告 3 = ボタン。値は 350 で割って ±1 で切る(速さの上限)。最後の報告から 250 ms 来なければ 0。報告 2 を受けた機器は、0 で詰めた長い報告 1 を移動だけと読む。
- 機器が 1 つも無い時は 3 秒ごとに探し直す(抜き差しに追従)。使う機器は 1 つ。
- ログ: つながった時に名前・番号・報告の形の手がかり・パス、報告の番号ごとに初めて来た時の長さと読み方(読めない形は warn)、初めの 8 回の報告の番号と長さ(debug)、外れた・権限が無い(1 回だけ)。毎コマの値は書かない。
- kmb-app が起動時に `Workspace::with_mouse3d(kmb_ui_mouse3d::open())` で渡す(安全モードでは探さない)。kmb-ui は `WinState::mouse3d` に持ち、設定の「マウス」の節に状態を 1 行出す。動き出しとボタンで描き直しを頼む。

## 決めたこと

- メーカーの開発キット・ドライバの口・hidapi の crate は使わない。OS の HID の口から直に読み、外の crate を足さない(Windows は windows-sys の機能を足すだけ、Linux は std だけ)。
- unsafe は `src/windows.rs` だけ(crate は forbid の代わりに deny)。

## 試し方

- 試験: `report::tests::decode`(6・12 バイト、ボタン、はみ出しの切り、250 ms で 0、詰めた報告)、`linux::tests::scan_fake_tree`(作り物の sysfs の木で多軸の機器だけを拾う)、`tests::fake_and_wanted`。
- 実機: 3D マウスをつないで起動し、設定の「マウス」の「3D マウス」の行が「つながった: 名前」になるか。ログの「3D マウスの報告 1(中身 N バイト)を…と読む」で報告の形を確かめる。視点はまだ動かない。
