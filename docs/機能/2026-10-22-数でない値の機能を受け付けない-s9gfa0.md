# 数でない値の機能を受け付けない

- 日付: 2026-10-22

## 作った物

2026-10-21 Kie が採用。MCP の `add_feature` に、読めないデータ(スケッチの点の位置に `"NaN"`・`"inf"`・null など)を渡すと、その場で断るようにした。

- 原因: 控えでは「型の付いた読み込みで弾くので済み」としていたが、確かめると `add_feature` は JSON をそのまま文書に入れ、読み込みは再計算の時まで行わなかった。そのため誤りの機能が文書に残り、後の機能も巻き込んでいた。入り口で中身を確かめていないのが元。
- 直し: kmb-session `headless.rs` の `add_feature` で、既定値を埋めた後に登録の `instantiate` で読めるか確かめ、読めなければ「○○ のデータを読めません: …」で断り、文書は変えない。
- 1e999 のような大きすぎる数は JSON を読む段で弾かれる。

## 試し方

- MCP で点の x を `"NaN"` にしたスケッチを `add_feature` すると誤りが返り、`status` の機能の数が変わらない。
- 試験 `kmb-mcp` の `a_sketch_with_a_non_numeric_position_is_refused`(直す前は失敗した)。
