# 構造のレビュー 段 3: 役割の印を型つきの印にし、語彙をコアから出す

- 日付: 2026-10-23

## 作った物

構造のレビュー 段 3 の 3 本目(計画の 3-1)。画面・CLI・MCP が操作・機能の種類・設定を探す役割の印 `jc_core::Role`(コアの閉じた列挙 24 種。3 つの語彙を兼ね、役割を足すたびにコアが変わった)をやめた。使う人から見える振る舞いは変えない。

- コアは印の型だけを持つ: 操作の `ActionRole`、機能の種類の `KindRole`、設定の `SettingsRole`(どれも文字の印)。語彙(押し出し・ボディを書き出す・機械・レンダリングのシーンなど)は jc-interchange の `role`(`action`・`kind`・`settings`)が定数で持ち、モジュールが名乗る。
- テンプレートから作る操作は、印 `USE_TEMPLATE` とテンプレートの名前 `Action::role_name` に分けた(前は印の中に名前を持っていた)。
- いくつの操作に付いてもよい印(テンプレートから作る・ボディを書き出す・自動分解)は `role::MARKERS`。
- 組み立ての試験(jc-bundle の tests/ids.rs): 名前と役割の一意に加え、語彙のどの印もどこかが名乗ることを確かめる(`every_role_in_the_vocabulary_is_claimed`)。この試験を AGENTS.md の点検の表(名前の一意)に入れた。
- 層の表で io と app も jc-interchange を使えるようにした(書き出しのモジュールが印を名乗り、CLI・MCP の短い命令が印で探すため)。
- AGENTS.md の「向かう先」を消し、段 3 の残り(アニメーション・外観・材料・構成の表の区画、ボディの長く使える ID)は plan.md の区画の段落へ移した。

## 決めたこと

- 印は 3 つの型に分けた(計画の文書の推奨どおり)。同じ名前でも型が違えば別の印で、取り違えると型の誤りになる。
- 画面のキーの行は、操作の印(`Does::Role`)と機能の種類の印(`Does::Kind`)を分けた。
- 出力の形: CLI・MCP の一覧の `role` は `{"kind": "extrude"}` から `"extrude"` になり、テンプレートの名前は `role_name` に出る。docs/入出力.md の役割の表は `action/…`・`kind/…`・`settings/…` で書く。

## 試し方

`cargo xtask verify --all`。jc-interchange の語彙の重なりの試験、jc-bundle の名前の一意と語彙の試験、画面の台本(押し出し・穴・外観のキー、スケッチの編集器の挿入と文字)。
