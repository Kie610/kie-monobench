# 文字のパラメータの型

- 日付: 2026-10-27

## 作った物

パラメータの表の単位の列で「文字」を選ぶと、そのパラメータは文字を値に持つ(`M3`、`{系列}-{長さ}`)。値は差し込みの文字で、`{ }` の中にパラメータの名前か数の式を書くと値が入る。数は文書の長さの単位で単位の字を付けて入る(`25 mm`、インチの文書なら `0.984 in`。`{長さ; 1}` は小数 1 桁)。構成表は式を入れ替えるので、行ごとに文字も替わる。パラメータの表・CSV と JSON の読み書き・CLI と MCP の状態の答えは、文字の値をそのまま出す(CSV の単位の列は `text`)。

機能は差し込みの文字の欄(`Field::template`)を持てる。入力は `template_inputs` で数え、値は `EvalCtx::text` で読む。文字の機能(kmb-text)がこれを使うのは別の本(Codex 50)。

## 決めたこと

- 差し込みの文字は kmb-expr の `Template`(読む・参照・値を入れる・名前の書き換え・消した寸法の式の差し込み)と `format_number`・`escape_template`。`{{`・`}}` は字。全角の括弧は字のまま。誤りは位置つきの構文の誤りと、文字のパラメータを数の式に書いた誤り(「文字のパラメータ X は計算に使えません」)、文字のパラメータに桁、長さと角度を掛けた値。
- 計算は数と文字のパラメータとモデルのパラメータを 1 つの名前の空間で依存順に解く。数の式が文字のパラメータを読んだら、そのパラメータだけを誤りにする。循環と名前の重なりは数と同じ扱い。結果は `ParamStatus::Text`(JSON は `{"status": "text", "value": …}`)、名前から文字の表は `RecomputeReport::text_values`。
- 新しい入力 `InputRef::Units`(文書の長さの単位)。差し込みのある文字は必ずこれを数える(名前 1 つの差し込みは、数か文字かが文書を見ないと決まらないため)。単位を替えると、差し込みのある機能だけが作り直される。文字のパラメータを替えると、それを読む機能だけが作り直される。
- 機能が数の欄に文字のパラメータを書くと、その機能だけが誤りになる(`EvalCtx::param`・`expr`)。
- 変更の確かめ: 文字のパラメータの式は差し込みの文字として読む。文字から数の単位に替える時、今の値が数の式でなければ断る。CSV で単位を文字に替える行は、単位を先に替えてから式を入れる。
- 名前の変更は文字のパラメータの式の差し込みの中だけを書き換える。寸法を消した時の差し込みも差し込みの中だけ。
- 保存の形の版を 7 に上げた(中身は前と同じに読める)。前のアプリは文字の単位を読めないので、新しい版の文書として断る。
- 単位の字の付け方と桁は画面の桁(mm・cm・m は 2、in は 3、ft は 4、角度は 2、単位なしは 6)で丸め、末尾の 0 を落とす。画面のスレッドの表示の単位は読まない(画面・CLI・MCP で同じ文字になる)。

## 足した言葉

文字(パラメータの単位の列)。

## 残した物

- 差し込みの欄で `{` の後にパラメータ名の候補を出す画面(今は文字の欄と同じに出す)。文字の機能の中で使う時に足す。
