# 書き出しの一本化と、誤りの種類

- 日付: 2026-10-22

## 作った物

構造のレビュー(2026-10-21)の段 1b(指摘 D10・D11)。

- 書き出しを `jc_session::write_output` に一本化した(D11)。同じフォルダの一時ファイルに書いて置き換え、「書き出した: パス(n バイト)」をログに残す。画面(文書の隣・名前を付けて・いくつものファイル・パラメータの表)、工具の書き出し、CLI、MCP の run_action・screenshot、Headless::write_files が通る。前は道ごとに `std::fs::write` を直に呼び、途中で落ちると半分の G-code が残り、ログの無い道もあった。`cargo xtask checks` の層の点検は、画面とアプリの層で `fs::write`・`File::create` を直に呼ぶ所を落とす。
- 誤りに種類を付けた(D10)。jc-core の `Problem { kind, message }`、種類は入力・計算・見つけた問題・使えない・ファイル。`Headless::run`(使えない操作)・`load`(読めないファイル)・`write_output`(書けないファイル)が種類を決め、文字列の誤りは入力の誤りになる。
- CLI の終了の番号を種類で分けた: 1 入力の誤り、2 再計算の誤り、3 確かめで問題を見つけた(シミュレーションの食い込みなど)、4 今は使えない操作、5 ファイルを読めない・書けない。`jc --help` の終わりに書いた。前は 2(再計算)のほかは全部 1 で、壊れた入力と食い込みを見つけたのが同じだった。
- MCP の誤りの答えは、文を content に、`{"kind": …, "message": …}` を structuredContent に入れる。batch の失敗は、失敗した手の種類を `failed.kind` と答えの種類にする。

## 試し方

- `jc run a.json io.export_stl --arg tolerence=0.1 --out x.stl` は 1、スケッチを選ばずに `jc run a.json cad.sketch.export_dxf --out x.dxf` は 4、`jc actions 無い.json` は 5 で終わる。
- 画面で STL を書き出すと、ログに「書き出した: …(n バイト)」が出る。
