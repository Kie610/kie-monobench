# セットアップが機械の値を文書に持ち、機械とポストの一覧を組み立てへ移す

- 日付: 2026-10-22

## 作った物

構造のレビューの段 4 の E3(機械とポストの選び方を組み立てへ)と E15(経路とポストで機械の値が違う)。Kie の判断は案 a(セットアップのデータに機械の値を写して持つ)。

- セットアップのデータ `cam.setup@…` に `machine_values`(機械の値の写し)を足した。「セットアップ」を足した時、設定の「機械」で選んだ機械と、その時の設定の値(作業範囲・回転数・早送りなど)を写す。経路の計算・欄の段階の知らせ・ポスト・G-code の検査・加工時間・段取り表・作業範囲の枠は、どれもこの写しを使う(`SetupInfo::machine_profile`)。
  - 前は、経路の計算(1 段の深さ・レーザーのはみ出し)がマシンライブラリの表の値、ポストと検査が設定で直した値を使い、同じ G-code に 2 通りの機械の値が混ざり得た。
  - 設定を後で直しても、今あるセットアップの経路と G-code は変わらない(文書だけで結果が決まる)。新しいセットアップから新しい値になる。
  - セットアップの欄で機械を替えると(写しの ID と欄が違う)、その機械のライブラリの初めの値を使う。写しの無い古い文書もライブラリの値。機械の欄の無い古い文書は `carvera-air`(`kmb_cam_setup::LEGACY_MACHINE`)。
  - 知らない機械はセットアップの評価で誤り(前と同じ)。
- マシンライブラリ `kmb_post::machines::MachineLibrary`(機械の値とポストの対の一覧)。組み立て `kmb_bundle::machines()` が Carvera Air と汎用の機械を入れて `install` し、`kmb_cam_commands::module(strategies, machines)` に渡す。ポストは機械の値の `post` の ID でライブラリから選ぶ(前は加工の操作が `LIGHTBURN_SVG`・`Generic::by_id` を名指しで選び、知らないポストは黙って組み立ての 1 台に落ちた。今はポストが無いと誤りの文を出す)。
- Carvera Air の値(作業範囲・ベッドの穴・レーザーと補正の命令・1 段の深さの表)を kmb-post から kmb-post-carvera-air(`machine.rs`)へ移した。kmb-post に残るのは汎用の機械(Fanuc 系・Grbl 系・SCULPFUN G20)だけ。
- 戦略の入力 `StrategyInput.setup.machine`(`MachineView`)に、戦略が使う機械の値だけ(加速度・ガルバノか・この材料と工具の溝の 1 段の深さ)を入れた。
- xtask の層の点検に「汎用の加工の crate(kmb-post・kmb-sim・kmb-cam-*・kmb-strategy-*・kmb-toolpath*)のコードと ID の文字列に機械の名前(carvera など)を書かない」を足した。今の例外は `MACHINE_KNOWN`(古い文書の互換の ID と、Carvera Air の工具一式)。

## 決めたこと

- 機械の値はセットアップが文書に写して持ち、経路・検査・ポストは同じ写しを使う(設定は新しいセットアップの初めの値だけ)。
- どの機械を一覧に入れるかは組み立てが決める。汎用の加工の crate は機械を名指ししない(xtask の点検)。
- Carvera Air の工具一式(kmb-cam-tool の carvera.rs)はまだ kmb-cam-tool にある。移すとテストが別の crate へ動き、消えたテストの点検で Kie の承認が要るため、次に機械を足す時にまとめて移す。

## 試し方

- `cargo test -p kmb-samples the_setup_keeps_its_own_copy_of_the_machine_values`。
- 画面: 設定の「機械」で作業範囲 X を直す → 今あるセットアップの「ストックが作業範囲を超える」の知らせは変わらない → 「セットアップ」を足すと新しいセットアップは直した値で知らせる。
