# 並列の作業場で共通部分を組み直さない

- 日付: 2026-10-29

## 作った物

- `cargo xtask warm`: 組み立てと入口の層より下の全部を、`verify` と同じ単位(テストの組み立てと clippy)で、テストを流さずに組む。組んだ後、自前のテストの実行ファイルと incremental を消す(`xtask/src/warm.rs`)。
- `scripts/cloud-target-cache.sh save-deps`・`restore-deps`: 共有フォルダに依存だけの写し(固めて約 0.6 GB)を全体の写しとは別に 1 組置き、戻す。`restore-deps` は今の target に無い物だけを足し、同じ組は 2 度戻さない。試験 `scripts/tests/cloud-target-cache-deps.sh`。
- `cargo xtask verify` と `warm` は、Linux で組み立ての前に `restore-deps` を流す(共有フォルダが無ければ何もしない。`JC_DEPS_CACHE=off` で止める)。
- 手順は docs/verify.md の 1 節「並列の作業場で共通部分を組み直さない」。

## 決めたこと

- 並列の作業場の共通部分は、作業場が準備の後の状態を取っておける所では準備の台本で `cargo xtask warm` を流し、共有フォルダのある所では依存だけの写しを戻して使う。
- 共有のコンパイルの取っておき(保存先に結果を置く道具)は使わない。
