# 機能の断片(1 機能 1 ファイル)

新しい機能を作ったら、作った物・決めたことを、このフォルダに 1 ファイルで書く(2026-10-21 Kie、構造のレビューの判断 4)。前は docs/plan.md の最後に 1 行ずつ足していたが、並行の PR が同じ所に足して取り込みのたびに衝突した。

特許の点検(調べた特許・先行例・判定・確定度)は公開する物に載せないので、ここには書かない(2026-10-24 Kie)。リポジトリの外の開発の記録に、断片と同じ名前のファイルで書く。点検で決めた避ける形は `docs/避ける形.md` に足し、断片には働きと理由だけを書く。

一覧の表はコミットしない。`cargo xtask docs` が断片から `target/docs/作った物.md` を作る。

## 名前

`日付-題-スレッドの末尾 6 字.md`(例 `2026-10-21-トレースとねじ切り-vrkuhk.md`)。末尾の 6 字は作業のブランチ `claude/project-thread-xxxxxx` の末尾(PC で書く時は英小文字と数字の 6 字なら何でもよい)。同じ日に同じ題を書いても重ならない。

## 中身

```markdown
# 機能の名前(画面の言葉で)

- 日付: 2026-10-21

## 作った物

何をどう作ったか。種類の名前(`cam.trace@1` など)と crate、欄、画面の場所。

## 決めたこと

(あれば)今後も守る決まり。plan.md・policy.md の決まりを変えた時は、そちらも直す。

## 足した言葉

(あれば)用語表.md に足した画面の言葉。

## 試し方

(あれば)人の操作手順での確かめ方、e2e の台本。
```

- 頭の欄「日付」は要る。plan.md・policy.md で「(決定: 名前)」を付けた Kie の決定を作った時は、欄「- 決定: 名前」(複数は「、」で区切る)を足す。印に無い名前は点検が落とし、まだ断片の無い決定は `cargo xtask docs` が一覧に出す(2026-10-23)。
- 節「作った物」は要る。ほかの節は任意。頭の「特許の判定」「確定度」と節「特許の点検」は書かない(点検が落とす)。
- 今効く決まりを変えた時は、断片に書くだけでなく、正本(policy.md・plan.md・verify.md・避ける形.md)の該当の所も直す。正本の節の最後に行を足し続けない。

## 点検

`cargo xtask verify`(と `cargo xtask checks`)が毎回、組み立てずに確かめる(docs/verify.md 1 節「点検」)。断片の形のほか、`xtask/names.txt` に名前が増えたか crate を足したのに新しい断片が無い PR を落とす。
