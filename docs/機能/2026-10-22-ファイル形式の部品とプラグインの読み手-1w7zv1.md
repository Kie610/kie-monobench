# ファイル形式の書き手を kmb-format にまとめ、ポストのプラグインの読み手を組み立てへ移す

- 日付: 2026-10-22

## 作った物

構造のレビューの段 4 の E12(同じ働きの写し)の一部と、E14(kmb-cam-commands の詰め込み)のうちプラグインの読み込み。画面の見た目と操作は変えていない。

- 新しい crate `kmb-format`(層 core、ほかの crate に依存しない)。zip の書き手と、書いた zip から名前で取り出す読み手、8 ビットの RGB・RGBA の PNG の書き手と RGB の読み手、DXF R12 の書き手(HEADER・線種と画層・LINE・CIRCLE・ARC・POINT・POLYLINE)、SVG の数の書き方と文字の置き換えと mm の紙の開きタグ。
- 使う側を移した: 3MF と工具の一覧の zip、MCP の絵(kmb-picture)と連番 PNG(kmb-io-render。png の crate は試験の読み直しだけに)、スケッチの DXF(kmb-io-dxf)と視点の DXF(kmb-io-stl)、スケッチの SVG(kmb-io-svg)と視点の SVG(kmb-io-stl)、LightBurn の SVG(kmb-post)、段取り表の文字の置き換え(kmb-cam-commands)。写しの基準 xtask/copies.txt から 1 組減った。
- ポストのプラグイン(WASM)を読む関数を、マシンライブラリ(`MachineLibrary::with_loader`)に入れて組み立て(kmb-bundle)から渡す。加工の操作(kmb-cam-commands)は kmb-plugin-host(wasmtime)に依存しなくなった。読み手の無い組み立てでは「この組み立てはポストのプラグインを読めません」。

## 決めたこと

- 書き出す数の書き方は形式ごとに呼ぶ側が決める(DXF のスケッチは往復で値が変わらない形、視点の線は小数 6 桁)。
- kmb-io-stl を STL・3MF と視点の線(図面の入り口)に分けるのはまだ。2 つの crate が共通に使う「書き出すボディ(引数 exclude を除いた見えるボディ)」の置き場(コアの API に足すか、層の決まりで io どうしの依存を許すか)を決めてから行う。

## 試し方

- `cargo test -p kmb-format -p kmb-io-stl -p kmb-io-svg -p kmb-io-dxf -p kmb-picture -p kmb-io-render -p kmb-cam-tool -p kmb-post`。
- 画面: 3MF・視点の DXF と SVG・スケッチの DXF と SVG を書き出して、前と同じソフトで開ける。
