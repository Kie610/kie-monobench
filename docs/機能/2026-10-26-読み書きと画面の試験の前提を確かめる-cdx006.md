# 読み書きと画面の試験の前提を確かめる

- 日付: 2026-10-26
- 意図: ほかの設計ソフトで報告された困り事(保存中に固まる、書き出しが止まる、網に穴、入れ子の部品で押し出せない、消して壊れる、欄が勝手に変わる、引く間に光る、大きな送り物で落ちる)が、このアプリでも起きないかを確かめたい。
- 仕分け: C 試験だけ(作りが違うので確かめ、期待と違う物は直さずに記録する)。

## 作った物

8 項目をそれぞれ調べ、6 項目は既存の試験と追加・拡張した試験で起きないことを確かめた。
本体の動作は変えていない。

| 項目 | 結果と確かめ方 |
|---|---|
| 保存中の更新 | 起きた。画面の保存は同期呼出しで、裏へ渡す作りではない。名前付き Ctrl+S 入力から保存と再読を実行したが、保存中も更新が続く試験の通過とはしない。 |
| ねじ穴の STEP | 起きない。M6 の貫通ねじ穴 2 個を持つ板を書き、読み直した体積・外形・面数を確かめる既存の試験を実行した。 |
| 細い面の表示と STL | 起きない。高さの差が 0.02 mm の形の表示用の網と、実際に書いたバイナリ STL を読み直した三角形で、各辺が 2 枚に使われることを確かめた。 |
| 入れ子の STEP の面から押し出し | 起きない。自分で書いた箱へ外箱→内箱→箱の二段の部品関係を付け、読み込んだ上面にスケッチを描いて結合で押し出し、体積が 4000 から 4500 mm³ へ増えることを確かめた。 |
| 消す前の下流の通知 | 起きない。既存の名前付き画面台本で消す操作を行い、直接・間接に使う機能名を消す前に示し、一緒に消す操作と取り消しも確かめた。 |
| 引く間の別の式 | 起きない。名前で蝶番を開き、一意な角度スライダを引く台本を追加した。別の欄の式を引いている複数のコマで読み、式が保たれ、角度が実際に変わることを確かめる。 |
| 引く間の形の強調 | 起きない。同じ台本の入力を通し、引いているカーソルが実際に形の上を通るコマで、形と機能の強調が無いことを確かめる。 |
| 大きすぎる MCP 要求 | 起きた。接続を終えて記憶の上限は守るが、種類付きの入力エラーを返さない。 |

形の試験は `kmb-solid` の `adopted_io_tests`、ドラッグ中の観測は `kmb-ui` の
`cmdline_tests::adopted` に置いた。画面の入力は `apps/kmb-app/tests/ui/` の台本を使い、
内部の値を直に変えずに部品の木を探して流す。別の式は `-55 deg * 2` と
`10 deg - 10 deg` を入れて確かめる。

## 決めたこと

保存は `save` → `save_noted` → `kmb_session::save_with` と画面の呼出しから同期して進む。
一時的な名前付きキー入力の観測では、10486 バイトの保存ができたコマは約 19 ms で、再読もできた。
この時間から大きい文書の停止時間や、保存中に画面が更新し続けることは主張しない。
同期保存は目的の前提と違うため、直しの期待で失敗する試験は残さない。

MCP は実プロセスの既定上限 16 MiB に対し、改行を除いて 16777217 バイトの完全な要求を送った。
初期化と短い `status` は成功するが、大きい要求は約 0.19 秒で応答なしの EOF となり、終了コードは 0 だった。
同じ読み手の上限を 4096 バイトへ下げた軽い試験でも、5000 字の ASCII 値を含む完全な要求は
種類付きの答えを返す前に接続が終わった。低い上限の試験と実際の既定上限の観測は分ける。
入力を読む `LineCap` が入出力の誤りを返す場所は、道具が `ProblemKind::Input` を作る場所より手前にある。
この返し方を期待して失敗する追加試験は残さず、既存の容量上限の保護と試験を保持した。
main に存在しなかった一時試験は、削除した既存試験の表へ載せない。

入れ子の面からの押し出しは成功したが、STEP の部品の配置は別の制約がある。
二段の配置へ X に 30 mm、Y に 20 mm の移動を付けても、読み込んだ箱の外形は
[0, 0, 0]〜[20, 20, 10] mm のままだった。配置を読まない実装の制約として記録し、
面にスケッチを描けない・押し出せないこととは同一視しない。

比較用カーネルでは、ねじ穴 STEP の再読、同じ面で接するブーリアン、読み込んだ面からの押し出しに
登録済みの飛ばしがある。これらを通過に数えない。
