# HRTF の天頂の取り方と立ち上がりの表の補い

- 決定: 音の解析とHRTF
- 日付: 2026-11-01

## 作った物

- `regrid` の欄 `pole`(輪の双線形の時だけ): `measured`(既定)は極の方向があればその値、無ければ一番上(下)の輪の平均。`ring_mean` は極の方向があっても使わず、極を一番上(下)の輪の平均で埋め、輪と極の間を仰角の比で混ぜる。輪の枠(立ち上がりを外した後)で混ぜるので、平均は立ち上がりをそろえた平均になる。
- `table` の欄 `onset_method`: 遅延の表の方向の立ち上がりを、集まりの方向から補う替え方(`nearest` 既定・`triangle`・`bilinear`)。集まり(例 2° の輪)より細かい遅延の格子(例 0.5°)で、間の方向の立ち上がりを隣の値の間に滑らかに入れる。半スペクトルは今までどおり最近傍。

## 決めたこと

- 2 つとも既定は今までの振る舞い(測った極を使う・最近傍)のままにし、手順で選ぶ。比べた表に合わせるのは手順の側で、ほかの手順の結果を黙って変えないため。
- `pole` を `ring_mean` にできるのは `bilinear` の時だけ。三角形と最近傍には極を埋める手順が無いので、選んだら入力の誤りにする。極のほかに輪が無い格子も誤り。
- 立ち上がりの補いは鳴らす立ち上がり(遅れ + 輪の枠の立ち上がり)を重みで混ぜる。共通の遅れはその後に引く。

## 確かめたこと

- 試験(2 本): 天頂の方向がある格子で、既定は天頂の値、`ring_mean` は天頂を使わず 45° の輪の平均 1/360 ずつ、三角形で `ring_mean` は誤り、JSON の `ring_mean` で選べる。30° の輪の集まりから 10° の遅延の表を作ると、`bilinear` は仰角に線形な立ち上がりをそのまま補い、最近傍では段になる。手順の JSON の `onset_method` で選べる。
- 実測の D1・KU100 での比べ直しは PC が要るので、まだしていない(not-run)。比べ直す時の手順は `regrid` に `"method": "bilinear", "pole": "ring_mean"`、`table` に `"onset_method": "bilinear"`。
