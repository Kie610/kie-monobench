# 重い計算中もほかのタブの画面を固めない

- 日付: 2026-11-09
- 意図: 1 つの文書で重い計算をしている間、ほかのタブの文書も固まる。
- 仕分け: C・JC に合わせて作る(形状カーネルの錠がアプリ全体で 1 つ。並べて動かせるかを確かめてから持ち方を決める)。

## 作った物

- 形状カーネル SMLib の錠は、すべての文書で 1 つのまま残す。SMLib の中には糸ごとに分かれていない作業用の値(曲線の当てはめの誤差の表、らせんの近似の値、誤りの入れ子の深さ、乱数の種など)があり、2 つの糸から同時に呼ぶと黙って形が狂うおそれがあるため(`crates/kmb-kernel-smlib/src/ffi.rs` の頭)。
- カーネルの呼び出しに「待たない糸」を足した(`kmb_core::kernel::set_kernel_wait`・`without_waiting`)。待たない糸では、ほかの計算が錠を持っていれば、待たずに `KernelError::Busy` で戻る。待つ糸(裏の再計算・CLI・MCP)はこれまでどおり錠が空くまで待つ。
- 画面は、表示の網・ボディの種類・辺の控えを待たずに作る。使用中で作れなければ前の網と辺のまま描き、`Scene::retry` と少し後の描き直しで作り直す(`kmb-ui-view3d` の `Scene`、`kmb-ui` の `scene_edges` と毎こま)。作れた網だけで置き換えないので、ボディが消えて見えない。
- 試験用に、ほかの文書の計算が錠を持っている間を作る `kmb_kernel_smlib::occupy`(組み立ての `kmb_bundle::occupy_kernel` からも使える)。錠を持っている間に戻ったか(`Occupied::still_held`)で、待ったかを時間で見ずに確かめる。

## 決めたこと

- 錠を外して文書ごとに並べて計算するのは、SMLib の作業用の値をすべて糸ごとに分けて点検し終えてから。それまでは錠を残す。
- 画面が後で作り直せる問い合わせ(表示の網・辺・ボディの種類)は `without_waiting` で呼び、使用中なら控えを残さない。操作の実行・測る・書き出しのように答えがその場で要る物は、今は待つ。

## 試し方

- `cargo test -p kmb-kernel-smlib --test busy`: 錠を持っている間、待たない糸の問い合わせ・押し出しは使用中で戻り、錠が空けば答える。待つ糸は使用中で失敗しない。
- `cargo test -p kmb-ui busy_kernel`: ほかのタブの計算が錠を持っている間に、網の細かさを替えてこまを描いても待たず、前の網のまま描き、計算が終われば作り直す。
