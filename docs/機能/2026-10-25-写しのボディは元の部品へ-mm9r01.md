# 写しのボディは元のボディの部品へ入れる

- 意図: 部品に入れたボディをミラー・パターン・移動のコピーで写すと、写しが文書の直下に出て、部品ごとに動かす・隠す・書き出す時に写しだけ取り残される。
- 仕分け: C・JC に合わせて作る。部品の木(`Component.bodies`)に写しを足す処理がどこにも無かった(crates/kmb-core/src/document.rs の `Component`)。JC は新しいボディの部品を計算の後に決める(crates/kmb-session/src/headless/active.rs の `settle_active`、アクティブな部品)ので、同じ所で写しの元の部品を決める。画面・CLI・MCP は同じ道を通る。
- 日付: 2026-10-25

## 作った物

- `settle_active` で、前の計算から後に足した機能のうち、ボディを写す機能が作った見えているボディ(まだ部品に入っていない物)を、元のボディの部品へ入れる。元は、機能が受け継がずに残すボディ(`keeps`: 移動/コピーの写し、種類がボディのパターン・ミラー)か、ボディを読まない機能なら最初に読む機能(パターンの写しを分けた機能が読むパターン)の、最初に作った機能でたどる。
- アクティブな部品があっても、写しは元の部品が先。部品の木の変更は写しを作った変更と同じ取り消し単位(アクティブな部品へ入れるのと同じ `squash_since`)。
- 試験: crates/kmb-ui/src/assembly/components_tests.rs の `copies_go_into_the_component_of_their_original`(直す前は写しが部品の外で落ちることを確かめた)。
