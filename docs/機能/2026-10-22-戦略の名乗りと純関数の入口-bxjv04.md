# 加工の操作から戦略の名指しを消し、戦略の計算を純関数の入口に分ける

- 日付: 2026-10-22

## 作った物

加工の核の 2 つ(戦略の名乗りと純関数の入口)。画面の見た目と操作は変えていない。

- 加工の操作(kmb-cam-commands)が戦略 4 つ(輪郭・面取り・ポケット・負荷制御粗取り)の名前と型を読んでいたのをやめた。戦略の名乗り `kmb_cam_setup::Strategy` に欄を足し、操作は名乗りだけを見る。
  - `floor_faces`: 3D のビューで底の面を足し外しできる(ポケット・負荷制御粗取り)。
  - `tool_order(adopt)`: 工具の順番を持てる。元の種類が使えない工具(負荷制御粗取りの後の V・テーパー)は、その工具を使える種類の `adopt` でデータを移す(ポケット)。
  - `cuts_free`: 部品を切り抜く(輪郭)。工具の順に並べ替える時に前へ動かさない。印 `cam.cuts_free` を組み立てで付け、経路の元 `PathSource::cuts_free` に入る。
  - 面取りの辺の選び直し(`cam.chamfer.edges`・`cam.chamfer.all_edges`)は、面取りの crate の `commands` に移した(操作の ID は同じ)。
  - kmb-cam-commands の通常の依存から kmb-strategy-* を外した(テストの依存には残る)。
- 戦略の純関数の入口 `kmb_cam_setup::StrategyInput`・`StrategyOutput`(kmb-cam-setup の plan.rs)。ホストの `Prepared::input` が、解いた値・セットアップの値(カーネルのハンドルを除く)・工具・切削条件・高さの決め方・形の箱・輪郭の領域を詰め、戦略の `plan` が経路と警告と使った高さを返し、`Prepared::finish_plan` が円弧のあてはめ・固定具の回避・つなぎの置き換えを当てて出力にする。輪郭の型(kmb-cam-geom の `Loop`・`Area`)を JSON にできるようにした。
- フェイス(kmb-strategy-face)を `plan(&StrategyInput) -> Result<StrategyOutput, String>` に分けた。`evaluate` は式とスケッチの輪郭を解くだけ。
- xtask の層の点検に 2 つ足した: 加工の層の戦略でない crate が戦略に通常の依存をしたら落とす。戦略のソースが `.kernel()`・`ShapeHandle`・`dyn Kernel` を使ったら落とす(今の例外はトレースの 1 か所、`STRATEGY_KERNEL_KNOWN`)。

## 決めたこと

- 戦略の違いは名乗りの欄で受け取り、加工の操作は戦略の crate に依存しない(policy.md 60 行)。
- 戦略を純関数の形へ移す時は、ホストで式・参照・網を解いて `StrategyInput` に入れ、`plan` は入力だけを読む。入力に足りない物(三角形の網・辺の折れ線・機械の値)は、移す戦略が要る時に `MachiningModel`・`Sources`・`SetupView` へ足す。
- 機械とポストの一覧を組み立てへ移すことは、経路の計算(セットアップの評価・戦略)が機械の値を kmb-post の固定の表から引くので、組み立てから渡す道が無い(種類の作り方 `Factory` が関数のポインタ)。セットアップのデータに機械の値を写して持つか、コアに渡す道を作るかを決めてから行う。

## 試し方

- `cargo test -p kmb-strategy-face`(`the_plan_reads_only_its_input_and_round_trips_through_json`)。
- 画面: ポケットを選んで底の面を足す・外す、負荷制御粗取りに V ビットを順番に足す(ポケットの残り削りになる)、面取りで辺を選んで「選んだ辺だけを面取りする」、輪郭の前にポケットがあるセットアップで「工具の順に並べる」が断られる。
