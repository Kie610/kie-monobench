# STEP の空洞を、殻の向きの印によらず空洞として読む

- 日付: 2026-10-22

## 作った物

STEP の BREP_WITH_VOIDS(空洞のある立体)を読む時、空洞の殻を空洞として読む(jc-kernel-truck `import.rs`)。SMLib のカーネルは STEP を自前の読み手で立体に組み(空洞の殻の向きは SMLib が縫う時に決める)、立体に組めない時だけ truck の網で読む(`with_step_import`)。どちらも印によらず空洞として読むことを試験で確かめた(SMLib は jc-contract の `shapes_we_make_read_back_from_step`、2026-10-25)。

- 原因: truck-stepio の表は殻(CLOSED_SHELL)だけを読み、どれが空洞かを持たない。JC は殻をどれも「囲む体積が正になる向き」にそろえていたので、空洞の殻も外向きになり、空洞が中身として足された(外 40³ − 空洞 20³ = 56000 の箱が 72000 になった。試験で再現)。
- 直し: データの節から BREP_WITH_VOIDS の空洞の並び(ORIENTED_CLOSED_SHELL の指す殻)を拾い、空洞の殻は囲む体積が負になる向き(空洞の側)にそろえる。向きは殻の印 .T./.F. で決めない(空洞の側を向いた殻に .F. を書く CAD と .T. を書く CAD がある。印で裏返すと書いた CAD によって逆になる)。
- third_party の truck-shapeops(ブーリアンの殻の内外の数え方)の直しとは別の所。truck-stepio には手を入れていない。

## 試し方

- 空洞のある形(箱の中に浮いた箱を引いた物)を STEP に書き出し、読み込むと、体積が空洞の分だけ小さい。
- 試験 `jc-kernel-truck` の `a_step_void_is_read_as_a_cavity_whichever_way_its_flag_points`(書いたままと、印を逆にした物の両方。直す前は 72000 で落ちた)。
