# 大きな設計でもパラメータの窓が軽い

- 日付: 2026-10-25
- 元の項目: 10-24 h7(大きな設計でもパラメータの窓が軽い)・10-20 u19(パラメータの表が重くない)
- 意図: 機能の多い設計を扱う人が、パラメータの窓を開くと画面がもたつく
- 仕分け: A・作る。先に測った: パラメータ 300・寸法 200 の文書(開発ビルド・CPU の描き方)で 1 コマ 閉じて 28.8 ms → 開いて 87.7 ms。パラメータだけ 300 で +31 ms、寸法だけ 200 で +20 ms。どちらも全部の行に入力欄を毎コマ置いていたのが元(使っている所の一覧は前から文書の版ごとに控えている)。

## 作った物

- パラメータの行と寸法の行は、前のコマに描いた場所が今見えず、入力中の欄も中に無ければ、入力欄を置かずに同じ大きさの空きだけを取る(`params_ui.rs` の `skip_row`・`skip_grid_row`)。巻けば出てきて、打っている欄は見えない所へ巻いても描き続ける。寸法の名前の欄に決まった id を付けた(描かない行があっても入力中の欄が入れ替わらない)。
- 同じ文書で 1 コマ 31.5 ms(閉じた時 28.6 ms)になった。
- 見えない行を描かない変更だけの時点で、台本「構成表」の写真 4 枚が前と画素まで同じだった。
- パラメータを足す行(名前・式・単位・追加)を、窓のいちばん下(寸法・フィーチャの値の後)から、ユーザーのパラメータの表の最後の行へ移し、名前・式の欄を表の列の幅に揃えた。単位は値の列、「追加」は削除の列に置く(10-20 u19 の後半。前は窓の幅が狭いと「追加」が右で切れていた)。前後の写真は同じ所の R15-前後-パラメータを足す行を表の列に揃える・下まで巻いた所。

## 試し方

- `jc-ui` の `rows_out_of_view_are_not_built_but_scroll_in_and_can_be_edited`(120 個の文書: 見えない行の欄は置かない → ホイールで下まで巻くと出てくる → p119 の式を打って Enter で決まる)。直す前は「見えない行の欄は置かない」で落ちる。
- 測る道具 `measure_params_window_on_a_large_design`(ignore。`JC_PARAMS`・`JC_SKETCHES` で数を変える)。
