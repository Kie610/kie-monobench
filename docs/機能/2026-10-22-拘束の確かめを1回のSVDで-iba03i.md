# 拘束を付けた後の再計算を速くする

- 日付: 2026-10-22

## 作った物

線 16 本ほどのスケッチで拘束を付けると、debug の組み立てで再計算に数分かかっていた(2026-10-22 の報告)。原因は 2 つあり、どちらも直した。

- 原因 1(debug だけ): 行列の計算(nalgebra の SVD)は総称の関数なので、呼ぶ側の crate の最適化で作られる。依存先は dev でも最適化していたが、呼ぶ側の kmb-sketch-solver が最適化なしだった。Cargo.toml の dev の設定で kmb-sketch-solver を最適化する。
- 原因 2(計算量): 解いた後の確かめ(自由度・余分な拘束・決まっている要素)と、拘束を足す前の「既に決まっていないか」の確かめで、変数ごと・拘束ごとに SVD を取り直していた(線 16 本で解くたびに約 110 回)。1 回の SVD で行の空間を作り(`kmb_sketch_solver::system::RowSpace`)、決まっている変数は単位ベクトルを空間から外した残りで、余分な拘束は行を順に足して空間が広がるかで調べる。0 と見なす大きさは前の `rank` と同じ。
- 測った値(debug、線ごとに端点を持ち一致の拘束でつないだ階段形): 線 16 本で solve 4.06 秒 → 0.096 秒、redundant_with 5.72 秒 → 0.105 秒。線 32 本で 29.1 秒 → 0.45 秒、42.7 秒 → 0.72 秒。
- 残り: 時間のほとんどは解く反復の中の SVD(線 16 本で 52 回)。線が 50 本を超えるスケッチで遅ければ、疎な行列の解き方に替える。

## 試し方

- 線 16 本の閉じた形に水平・垂直・長さ・一致の拘束を付け、拘束を 1 つ足して再計算が 1 秒かからないこと。
- 試験 `kmb-sketch-solver` の `row_space_agrees_with_taking_the_rank_again`、kmb-sketch の既存の拘束の試験(余分・矛盾・自由度)。
