# 分かれた面の切れ端が、計算し直しても同じ名前を保つ

- 日付: 2026-10-22

## 作った物

面がブーリアンで分かれた時の切れ端の名前(`f2:end#0` など)が、同じ設計を計算し直しても入れ替わらないようにした。後ろの機能(フィレット・穴の止める面・スケッチの面など)が面を名前で指すので、入れ替わると別の切れ端を指す。

- JC は前から、切れ端の番号を代表点の位置の順で付けていた(「カーネルの並びの順」で番号が変わる誤りは JC には無い)。調べると次の 2 つが残っていた。
- 原因 1(truck、試験で再現): 同じ平面の元の面が複数ある時(前に分かれた切れ端をさらに切る時)、結果の面は「先に見つけた元の面」の名前を継いでいた。truck の結果の殻の並びは実行ごとに変わるので、同じ操作を繰り返すと `a:end#0#…` と `a:end#1#…` が入れ替わり、どの切れ端も同じ元の名前になって入れ子の番号が付いた。SMLib は面の印で継ぐので起きない。直し: 結果の面の代表点を含む(網までの距離がいちばん近い)元の面の名前を継ぐ(jc-kernel-truck `shells_of`)。SMLib と同じ名前になる。
- 原因 2(両カーネル): 位置の比べ方が 1 µm の格子に丸めた辞書順だったので、丸めの境にある座標(0.4999 µm と 0.5001 µm)のわずかな揺れで、y で並ぶはずの番号が x で決まり入れ替わった。直し: 1 µm より近い座標は同じとみなし、次の座標で比べる(jc-core `dedupe_names`)。
- 今の文書への影響: 1 µm より近い座標の切れ端と、truck で同じ平面の元の面が複数あった所だけ名前が変わる(どちらも前は揺れていた所)。保存形式は変えていない。

## 試し方

- 試験 jc-contract の `pieces_of_a_split_face_keep_their_names`(両カーネル。上の面を溝で 2 つに分け、片方をさらに切り欠いて 5 回繰り返す。直す前の truck は 3 つとも `a:end#1#…` で落ちた)。
- 試験 jc-core の `dedupe_ignores_jitter_below_a_micrometre`(直す前は x 0.4999 µm と 0.5001 µm で番号が入れ替わり落ちた)。
