# 画面で開いた文書の隣へ AI が保存できる

- 日付: 2026-11-09
- 意図: AI に形を作らせる時、開いた文書の隣へ保存できず、見込み違いに気づくのが遅れ、値を試すたびに何度も呼ぶ要がある。
- 仕分け: B・土台から作る(許すフォルダは起動の時だけ。見込みと試す手を Headless のまとめて流す手に足す)。

## 作った物

AI(MCP)が読み書きできるのは作業フォルダと `--allow` で許したフォルダだけなので、人が画面で開いた文書の場所を AI が知って(`app` の `status` の `file`)その隣へ保存・書き出しすると断られていた。MCP の開く・保存は同じ確かめを通るので、AI が自分で開いたフォルダではこれは起きず、起きるのは画面で人が開いた文書のフォルダだけだった。

- MCP は、許しの外のパスで断る前に、動いている画面の今のタブで開いている文書を聞き(`kmb_session::live::open_document`)、パスがその文書のフォルダの中なら、そのフォルダを許して通す。許しはその MCP の接続の間だけで、覚えて残さない。
- 通るのはファイルの道具(`save`・`export`・`screenshot` の `out` など)と、操作のファイルの引数(`run_action`)。許したフォルダは、その後の `app` の頼みにも添わる。
- 許し方は kmb-session の `Roots::allow_document_folder`。ドライブの直下とホームのフォルダ(とその上)は広すぎるので許さず、断る誤りにわけを添える。そこを使うなら起動の `--allow` で許す。
- 画面が無い・保存先の無い文書・画面が 10 秒で答えない時は、今までどおり断る。

## 決めたこと

- 画面で開いた文書のフォルダは、確認を挟まずにその回だけ自動で許す。人が自分でそのフォルダを開き、AI との接続も自分で入れているため。
- 画面で開いていないフォルダは、AI が指しても許さない。

## 試し方

- 試験 `kmb-mcp` の `saving_next_to_the_document_open_on_the_screen_is_allowed`: 画面が無い間は断り、画面の代わりが文書を開いている間はその隣へ保存でき、開いていないフォルダは断る。
- 試験 `kmb-session` の `a_document_folder_is_allowed_but_not_a_drive_or_the_home`。
