# HRTF の形式をそろえる道具の土台

- 決定: 音の解析とHRTF
- 日付: 2026-11-01

## 作った物

- crate `kmb-hrtf`(層 analysis)。画面・操作への登録はまだ無く、ライブラリだけ。
- 型 `HrirSet`: 方向(SOFA の球座標。方位は前から左回り、仰角は上が正)、左右の HRIR、左右の遅れ、IR の中の立ち上がり、置き方(時間の並び・輪の枠)、元の属性(題・許諾など。知らない鍵も保つ)、通した処理の記録。
- 処理の手順 `Recipe`(JSON の段の並び)と入口 `run`。段は次の 5 つで、知らない段・欄は誤りにする。
  - `onset`: 3 kHz の低域を 8 倍に補間し、頂点の −10 dB を初めて超える点を立ち上がりとする。外す時は遅れへ移し、長さ F の輪の枠に置き直す
  - `combine`: 大きさを A、位相を「A の最小位相 + B の位相 − B の最小位相」にする(片方の音色に、もう片方の時間を付ける)
  - `shift`: 立ち上がりを別の集まりの立ち上がり + n sample に合わせる
  - `trim`: 立ち上がりの前後を残す窓(端は半ハン窓)と、決めた周波数から上のならし
  - `table`: 時間差を除いた半スペクトルと遅延の表を書き出す
- 分けた表の形: 輪の格子(仰角の刻みごとの輪に round(360 cos(el) / 刻み) 方向)。半スペクトルは F = 512 の 0〜256 番を左右の実部・虚部で float16、遅延は 0.5° の格子で左右を float16(幅 1024 に並べる)、輪の表は float32、大きさは layout.json。引き方は輪と方位の最近傍。共通の遅れ C = max(floor(最小の τ) − 前 − 頭の空き, 0) を引ける。
- FFT(2 の累乗の基数 2)と float16 の変換(f64 から直に偶数への丸め)は自前。外の依存は足していない。

## 決めたこと

- 処理はファイルにも文書にも触らない純関数にし、書き出しは名前とバイト列を返す。置くのは呼ぶ側の壊れない書き込み。
- 格子をそろえる処理(`regrid`)が入るまで、表の方向は最も近い測定の方向の値を取る。`combine` は方向の並びが同じ集まりだけを受ける。
- HRIR は実数の列で持つので、表のナイキストの 1 点は小数の立ち上がりの位相を持てず実部だけになる。

## 確かめたこと

- 試験 14 本: FFT と素の DFT の一致、float16 の全部の有限値の往復と偶数への丸め、2° と 0.5° の輪の格子の方向の数(10318・165016)と引き方、最近傍の索引と総当たりの一致、立ち上がりが遅れに付いて動くこと、最小位相の大きさ、窓の形、手順の JSON の往復と知らない欄の拒否、表を鳴らすと元の HRIR に float16 の丸めの範囲で戻ること、`combine` の大きさと時間、`shift`・`trim`・共通の遅れ、そろっていない入力の誤り。
