# AI とコマンドで作業する部品(アクティブな部品)を決める

- 日付: 2026-10-24

## 作った物

- 作業する部品の状態(どの部品か、その間に作った物を覚える控え)を、画面の文書ごとの状態から `kmb_session::Headless` へ移した。計算の後に、作ったボディと文書の直下に作った部品をその部品へ入れる処理(`Headless::settle_active`)も 1 つにし、画面は裏の計算を取り込んだ後に、CLI・MCP はその場の計算の後に同じ処理を通る。入れる変更は作った変更と同じ取り消し単位。複製した部品は作った部品のまま。
- MCP は `activate_component`(`component` を省くと文書の直下へ戻す)。`status` に `active_component` が出る。CLI は `jc run` と `jc feature add` の `--component N`(1 回ずつ開くので、その実行の間だけ有効)。無い部品は誤り。
- 文書には保存しない(開いている間だけの状態。開き直すと文書の直下に戻る)。

## 点検(8-1)

- 「画面の変更の組み立て」: 画面の層とアプリ(kmb-app)で、文書の変更を `kmb_session::edit::…(` や `Transaction::new(` でその場で組む所を数える。今ある 18 ファイルの数を xtask/src/layers.rs の `SCREEN_EDIT_KNOWN` に置き、増えたら落とし、減ったら数を直させる。「画面の Op」は `Op::` の字面だけを見ていて、edit で組むと素通りしていた。
- 「画面の呼ばない口」(逆向き): `Headless` の文書を変える口(`pub fn …(&mut self`)のうち、画面が `work.名前(` で呼ばない物を数える。今の 33 個を `SESSION_ONLY_KNOWN` に置き、新しく CLI・MCP だけの口が増えたら落とす。画面が呼ぶようになった物は表から消させる。

## 試し方

- 試験 `kmb-mcp` の `the_ai_activates_a_component_and_new_bodies_go_into_it`、`kmb-cli` の `a_feature_made_with_component_goes_into_that_component`、画面は既存の `kmb-ui` の `bodies_made_while_a_component_is_active_go_into_it` と丸のボタンの試験、タブを閉じた時の試験。点検は xtask の `edit_builds_count_the_change_builders`。
