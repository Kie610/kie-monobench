# 構造のレビュー 段 3: コアから個々の機能の語彙を出す(描き方の役割・辺のたどり・控え)

- 日付: 2026-10-23

## 作った物

構造のレビュー 段 3 の 1 本目(計画の 3-2・3-5・3-6)。コア(kmb-core)が個々の機能の知識を持っていた所を、モジュールの側へ移した。使う人から見える振る舞いは変えない。

- 描き方の役割(3-2): `LineInk`・`BoxInk`・`PlaneInk`・`MarkKind` を、コアの閉じた列挙から文字の印の型(`LineInk("travel")` など)にした。`ShapeInk` は操作の番号と sRGB のほかを `ShapeInk::Named` にした。語彙(早送り・寄る線・安全高さ・削り過ぎ・刃など)は kmb-interchange の `ink` が定数で持つ。画面のテーマ(kmb-ui-view3d の ink.rs・view3d.rs)は定数ごとに色を決め、知らない印は主の線(形は操作の最初の色、平面は安全高さの色、印は削り残しの色)で描く。画面と kmb-session の層が kmb-interchange を使えるよう、層の表を広げた。
- つながる辺のたどり(3-6): kmb-core の chain.rs を kmb-cad へ移した。画面の辺のダブルクリックは、拡張点 `Extension::edge_chain` で CAD のモジュール(kmb-cad の InspectCommands)に頼む。辺の「なめらかな継ぎ目」の印(`EdgeInfo::smooth`、分からない時も偽)を `Seam { Unknown, Corner, Smooth }` にし、たどりは `Corner` の辺へだけ進む(分からない辺では止まる)。truck は両側の平面の法線から求め(前は常に偽で、継ぎ目の上も黙ってたどった)、SMLib の平面どうしの辺も法線から求める。両方のカーネルで同じ契約テスト(`edges_know_whether_they_are_corners_or_smooth_seams`)を流す。
- 実行時の控え(3-5): 解析の解く仕事の預かり所(kmb-study の `STORE`)を、kmb-study のモジュールが置く組み立てごとの共有の値(`Prepared`)にした。デカールの読んだ絵の控え(kmb-render の `CACHE`)は、画面の窓の状態とレンダリングのモジュールの共有の値に持たせた。どちらも static の既知の表(xtask/src/layers.rs)から消した。

## 決めたこと

- 描き方の役割と(段 3 の後半の)役割の印の語彙は kmb-interchange に置き、コアは印の型だけを持つ(計画の文書「構造のレビュー 段 2・3 の計画」の決めてほしいこと 2、推奨どおり)。
- 解析の預かり所は、計画では「開いている文書が持つ」としたが、鍵が条件から作る値で文書をまたいでも混ざらないので、組み立てごとの共有の値(段 2b-3 のシーンの設定と同じ形)にした。
- 辺のつながりの許しの角度は、カーネルの継ぎ目(`kmb_core::kernel::SEAM_DEG`)とたどり(`kmb_cad::TANGENT_DEG`)で別に持つ(どちらも 2°)。

## 試し方

`cargo xtask verify --all`。辺のダブルクリックで角を丸めた長方形の縁が一周選ばれること(kmb-ui の選択の試験)、加工の経路の線の色が前と同じこと(kmb-ui-view3d の ink の試験と画面の台本)。
