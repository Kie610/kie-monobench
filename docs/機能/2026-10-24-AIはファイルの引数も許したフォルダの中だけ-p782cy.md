# AI はファイルの引数も許したフォルダの中だけを読む

- 日付: 2026-10-24

## 作った物

AI(MCP)が読み書きできるのは、作業フォルダと `--allow` で許したフォルダだけ。これまで確かめていたのは道具の `file`・`out` だけで、操作の引数に書いたパス(デカールと下絵の `path`、フォントの `file`)はそのまま読んでいた。そのため、許していないフォルダの絵やフォントを文書に取り込めた。

- 操作がファイルを読む引数は、kmb-core の `ArgKind::File`(`Arg::file`)で宣言する。確かめ方は文字の引数と同じ。
- 許したフォルダの確かめは kmb-session の `roots::Roots` に置き、MCP の `run_action`・`batch` は実行の前にファイルの引数を許したフォルダの中の絶対パスへ置き換える。外を指せば、どの操作のどの引数かを添えて断る。
- MCP の `app`(動いている画面への頼み)は許したフォルダを頼みに添える(`live::call_confined`)。画面は、その頼みで動く操作(`run`、`command`・`script` の `run` の行)のファイルの引数を同じく確かめる。人が画面やコマンド欄で動かす操作は限らない。

## 試し方

- 試験 `kmb-mcp` の `every_file_arg_of_every_action_stays_inside_the_allowed_folders`: どの操作もパスらしい鍵を文字の引数で受けず、ファイルの引数に外のパス(絶対パスと `..`)を渡すと断る(点検: 許したフォルダ)。
- 試験 `kmb-session` の `file_args_are_confined_to_the_allowed_folders`。

## 残り

- 設定のポストのプラグイン(.wasm)のパスは設定の欄(文字)なので、MCP の `set_settings` からは確かめていない。欄の型にファイルを足す時に合わせて限る。
- 部品のリンク(外の文書を参照する部品)は文書が指す先を読む。AI が開いた文書のリンクの先を限るかは別に決める。
